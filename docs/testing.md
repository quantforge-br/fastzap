# Testing

## How to run

```bash
pnpm check                      # svelte-check + TypeScript
pnpm test                       # Vitest (src/**/*.test.ts)
cargo fmt --manifest-path src-tauri/Cargo.toml --check
cargo clippy --manifest-path src-tauri/Cargo.toml --all-targets -- -D warnings
(cd src-tauri && cargo test --locked)   # also regenerates src/lib/ipc/generated/
```

CI fails when a generated file diverges from the committed one: the `frontend`
job runs `pnpm i18n` and compares `src/lib/i18n/catalogs/`; the `rust` job, on
Linux, compares `src/lib/ipc/generated/` and
`src-tauri/permissions/autogenerated/` after the tests. Clippy and tests use
`--locked`: a new dependency without an updated `Cargo.lock` fails before
compiling.

## Suites

Rust tests live next to the code (`#[cfg(test)] mod tests`). Each area covers:

- **settings**: defaults matching ZapZap's, reading partial or corrupted
  files, JSON version migration.
- **migration**: `ZapZap.conf` with text booleans, inverted `quit_in_close`
  key, legacy keys (`system/wayland`, `downloads/auto_open_media`),
  `zapzap.db` database, and `storage-whats` → account 1 mapping.
- **webview**: navigation allowlist, deep links, per-account User-Agent;
  every `shortcutFor` action in `bridge.js` is in `REMOTE_ACTIONS` (or is
  `paste_plain_text`).
- **notifications**: global/per-account policy, name and text hiding.
- **evolution**: REST client with `wiremock` (admin vs instance scope,
  full and merged connect payload, capitalized fields, sanitized non-2xx
  errors, send timeout → ambiguous result, journal with and without cursor,
  reconnect); WebSocket against a local `tokio-tungstenite` server (double
  decoding, `instanceToken` stripping, instance filter, 20 MiB frame,
  reconnection, renewal that only reconnects after the server has closed the
  old socket); event parser (text, reply, unwrapped media, reaction, edit,
  revocation, receipts, HistorySync, business messages with buttons and
  header media, polls, button replies, album items, round video, download
  proto with only `directPath`); SQLite store (deduplication, outbox,
  receipts that only advance, late failure that does not demote a confirmed
  message, journal page applied in order with the cursor, count of messages
  only the journal brought, origin switch that clears the database, pages,
  history-sync anchor, names; stored buttons; opening released stores
  (`0.1.0-rc.1` v1, `rc.2`/`rc.3` v2) from the DDL copied from each tag;
  v4 store with messages, quotes, and unsupported previews that the
  migration to schema 5 re-reads). Every released version with a new
  `user_version` gains a fixture with the tag's DDL. The 65 s WebSocket
  deadline without frames and the session's periodic journal read have no
  automated test.
- **customizations**, **downloads**, **reporting**: pure file, history, and
  sanitization rules.

Frontend tests (Vitest) cover pure functions in `src/lib/` (formatting, i18n,
validation, `src/lib/evolution/format.ts`) and compare the local shortcut map
with `bridge.js`'s `shortcutFor`, evaluated from the script.

## Packaging

`packaging/common/version.sh --check`, `desktop-file-validate`,
`appstreamcli validate --no-net`, `shellcheck`, and `actionlint` validate
metadata, scripts, and workflows (the first four also in the `packaging` job
of `quality.yml`). The packages themselves are only verified by building
them; see [maintenance](maintenance.md#packaging). The Arch installer is
validated with `shellcheck packaging/arch/install.sh` and
`bash -n packaging/arch/PKGBUILD`. Its smoke test is `make install` on Arch
Linux: check the local version with `pacman -Q dsr-fastzap-git`, the ownership
of `/usr/bin/fastzap`, and that only `fastzap.desktop` exists in the package.
`sudo make install` must be refused before compiling or installing.

## Manual checks

Child webviews, focus, tray, notifications, and the composer cannot be verified
in automated tests. Before releasing, run `pnpm tauri dev` and check: two
isolated WhatsApp Web accounts, unread counter, notification click, tray,
second instance with `xdg-open "whatsapp://send?phone=..."`, downloads
(WhatsApp Web and Evolution Go chat document in the history, also after
disabling and re-enabling the WhatsApp Web account and after blocking a download
in the multiple-downloads prompt and resetting the permission), page reloaded
after `kill -9` on the account's `WebKitWebProcess`, theme, and grid (cards for
all accounts, including disabled and Evolution Go ones; the card opens the
account).

Without a PipeWire server (isolated D-Bus session/test runtime), the
`pipewire-alsa` plugin deadlocks the web process when WhatsApp opens the audio
output and the page goes blank; in those environments point `ALSA_CONFIG_PATH`
at a file with `pcm.!default { type null }`.

For Evolution Go, first use the read-only probe of the
`evolutiongo-integration` skill. Real pairing and sending only with an
authorized test account and recipient.

### Drag-and-drop attachments

- WhatsApp Web: drop files from the file manager onto the conversation; check
  that the drop zone shows while dragging and goes away when the drag leaves
  without dropping, the page preview, with no navigation to the file, including after switching
  accounts, with several files, with a zoomed account (drop position), and
  with a folder or a file over 100 MB (toast in the page, nothing attached).
- Evolution Go: drag several files over the conversation; check the highlight,
  names, and individual removal. Dropping does not send: Send confirms, with an
  optional caption. Repeating the same path does not duplicate the attachment.
- Dropping onto the chat list, settings, or outside the conversation does not
  attach; offline, editing, and in-progress sending also accept no new
  attachments.
- Check interface scale and HiDPI, leaving the drag without dropping, folders,
  missing file, empty file, and the 100 MB limit. Rust tests in
  `upload::tests` cover the read limits.
- With a mock server, force a failure on the first of several files: the
  following ones stay pending and the attempted one is not automatically
  retried. Switch/close the conversation during sending: the next files do not
  go out and completion does not clear the new conversation's draft.
  Closing/reopening must not accumulate listeners. No real sending without an
authorized recipient.
